# KISS Runtime Output

对话内容的排版层。它不改执行、不改品牌、不替换任何 React 节点，只给转写稿（transcript）里的三种声音分配各自的角色：

| 声音 | 之前 | 现在 |
| --- | --- | --- |
| 助手正文 | 和工具行同色同重的一列灰字 | 文章：小节标题 15 px / 600，上方一条发丝线，段前留白 |
| 工具调用 | 一行摘要，要点击才看得到命令 | 边注：标签 11.5 px、摘要 12 px，都跟随界面字体；只有文件路径保持等宽。**最新一轮的 shell 命令默认展开**，行头保留描述；**读取图片显示 44 px 行内缩略图**，点缩略图仍是原图浮层 |
| 思考 | 逐字刷新的英文思维链，行高跟着跳 | 只留一个「思考」标签；原始推理点开才显示，不跳、不占视觉 |

配合 [`@local/kiss-brand`](../kiss-brand/README.md)（显示名 **KISS Runtime UI**，品牌/外观层）使用；两层互相独立，可分别停用。

## 输出约定

排版只能放大结构，不能创造结构。这一层成立的前提是回复本身这样写：

1. **每步一个短标题**，`##` 或 `###`，动词开头，不超过 12 字。
2. 标题下先用一句话说意图，再动手。
3. 动作交给工具，正文不复述命令。
4. 动作后接一句带数字的结论。
5. 连续的同类动作合并成一步。
6. **工具描述用中文短句**，它就是这个工具行在界面上唯一的人话。

没有标题时，插件只会把行距收紧，看起来仍然是日志。小节标题只能由模型写——Cursor 的 `Ran command` 可以从工具名派生，但「这一步在干什么」派生不出来。

## 实现

一个 `<style>`，加一个很小的自动展开控制器：

- 只处理**最新一轮**里的 `bash` / `pwsh` 行，更早的轮次保持折叠。
- 每个 `callId` 只自动展开一次；读者手动收起的行不会被重新打开。
- 最新一轮里的 shell 命令与图片读取默认展开，单次最多 24 条；更早的轮次保持折叠。
- 展开靠点击行自己的 disclosure，不伪造开合状态；DSH 的终端卡片、退出码和截断规则原样保留。

选择器只用 DSH 公开的对话契约：

- `data-chat-flow-kind`（`assistant-step` / `tool-call` / `turn-tail` / `turn-process`）
- `data-chat-anchor-key`（`group:` 前缀标识过程组）
- `data-chat-group-part`（`reasoning` / `response`）
- `data-variant`（工具视图类型：`bash` / `read` / `edit` …）

以及 CSS Modules 的稳定前缀 `[class*="_markdown_"]`、`[class*="_summary"]`、`[class*="_title"]`。DSH 升级改了类名时，最坏情况是这一层失效、界面回到原样，不会报错或卡住。

## 安装

```bash
plugin_manager install_bundle target=/path/to/dsh-kiss-output
```

`cordis.patch.yml` 只插一行 `kiss-output`，不覆盖任何官方条目；移除本插件即回到默认排版。

## 已知边界

- 折叠状态下，工具行显示的是模型的 `description`；展开后才是原始命令与输出。自动展开只覆盖最新一轮的 shell 调用，读文件、搜索仍然保持一行。
- 展开卡片的输出高度由 DSH 的终端卡片决定（约 224 px），超出部分在卡片内滚动。
- 想更接近 Cursor 的"一次只露一条"，把「工作步骤展示」切到**简洁**：运行中的过程会收成一行组头，点开才是整组。
